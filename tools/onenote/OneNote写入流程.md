## 二、直接执行（三步）

```bash
cd ~/flight-repos/pub/tools/onenote
python3 onenote_auth.py      # 1. 登录：屏幕给出网址和代码，请用户自己在浏览器登录并同意（令牌存 ~/.config/flight-onenote/，自动续期）
python3 onenote_build.py --docx ~/Desktop/飞行理论笔记整理/Muse交接包/B737机型理论知识笔记_基线<号>.docx   # 2. 写入全部 69 页 + 补图 + 核查（默认写入「B737 机型理论知识笔记」笔记本）
# 只改了少量段落时：python3 onenote_patch.py --docx <同上> --sections 1.5,3.11 --dry   先预演，再去掉 --dry 执行（逐段替换，保留页序和插图）
python3 onenote_build.py --docx <同上> --audit-only   # 3. 再做一次只读核查，确认不缺页、不重复
```

- 写入同名页之前，脚本会先删掉旧页，所以重跑等于整组更新。
- `--only 3.6,3.7,…` 只重写这几节。**接口不能调整页序**，重写某一节时，同一分区里它后面的节要一起重写，否则这一节会排到分区末尾。
- `--figs-only` 只补插图。已有的图会跳过，不会重复插入。
- 分区组、分区不存在时，脚本会自动新建。**接口不能删除分区组和分区**，要删只能在 OneNote 界面里右键删除；删掉的分区会进「已删除笔记」。

## 三、为什么这样做（踩过的坑）

1. **Mac 粘贴行不通**：粘贴 HTML、RTF，甚至从 Word 复制，OneNote 都会把字体重置成微软雅黑，居中变成靠左，宽度也不保留，只剩颜色和粗体。所以必须走 Microsoft Graph 接口。
2. **登录**：设备码方式，客户端用微软官方的「Microsoft Graph Command Line Tools」，权限 Notes.ReadWrite，账号类型 consumers（个人微软账号）。用户自己在浏览器登录，Claude 看不到密码。访问令牌有效期 1 小时，用续期令牌续期。
3. **宽度**：页面上只有一个正文框时，OneNote 会把文字限在约 545px 处换行，设多宽都没用（Mac 和 iPad 都这样）。每页先放一行灰色页眉「章 ｜ 节」作为第二个正文框（top 110px），正文框（top 140px）的宽度就会生效。文字的有效宽度约是正文框宽度的 0.93 倍，表格约 0.95 倍，所以正文框 700、表格 670 时两者大致对齐。
4. **表格**：边框要在 `<table>` 上写 `border="1"`，只写 CSS 会被存成 0px。不支持合并单元格（合并格会拆开，内容放在第一格）；不支持单元格上下居中。
5. **转换（onenote_conv.py）**：
   - LibreOffice 的 `<font face>`、`align` 这类旧写法，要转成每个 span 的 `font-family` 和段落的 `text-align`；
   - 段落里的换行还原成空格，否则「A-1 发动机」会变成「A-1发动机」；
   - 两张表之间的「两个换行」分隔段改成一个矮空段；
   - LibreOffice 转 HTML 会把插图和图注一起丢掉，所以插图另从 `notes_src/figures/` 补。
6. **建页不要盲目重发**：网络超时后重发建页请求，会造成重复页。脚本的做法是：先记下同名页清单，异常后再查一遍，有新页就当作已建成。
7. **新建的页可能读不到或标题为空**：服务器有时会留下读不到内容的「坏页」，或者标题是空的。每页建完都要读回确认，读不到就删掉重建；标题为空就用 `PATCH target=title` 补上。
8. **删除时返回 404 的残影**：列表里可能残留读不到的副本，删除时报「不存在」，可以忽略，以「可读页」为准。**不能按编号判断重复**：编号可能会变，判断重复要看同一分区里可读页的标题。
9. **插图**：用 `PATCH` 的 multipart 请求（Commands + 图片部件），在锚点段落前或后插入「图 + 图注」。锚点取源文件 `%%FIG%%` 的前一行，如果前一行是表格，就取后一行并插在它前面。成品里相邻两行会合并成一段，「详见」只显示到节号，所以按「段落包含这段文字」来匹配。宽度按 毫米 ÷ 270 × 670 换算。
10. **Mac 界面操作**：同步用 File → Sync This Notebook；锁屏时截不到图。删除分区组要在界面里右键删除，删前截图确认点中的是哪一组。

## 四、写完要核对

- 每个分区的可读页数：第一～五章依次为 14 / 7 / 12 / 23 / 13，不缺页、不重复；
- 抽查读回的页面：来源 / 出处行为 0，没有块索引，有两个宽 699px 的正文框，字体是 Songti SC；
- 插图 17 张，每张前面最近的小标题要和源文件一致（1.1 有 3 张，1.2、1.8、1.14 各 2 张，其余各 1 张）。

## 五、2026-10-05 补充的坑

11. **跨笔记本移动页面会丢插图**：移动后要用 `--figs-only` 重新补图。补图遇到 504 超时时，图往往已经插进去了，重跑会自动跳过已有的图。
12. **改名、删除笔记本只能在界面里做**（接口不支持）。同名笔记本要先删掉，否则改名会冲突。
13. **拆页要排除第零章**：速查区里有和正文同名的节（如「1.5 电气」），按标题选节时会选错。
14. **全文核对**：只比段落会漏掉表格里的差异。最后核对时要把每页全部文字（含表格）和新基线的转换结果逐字对比；以前就是这样查出 4.21 漏了一段正文。


## 六、每次出新基线后的同步（用户 2026-10-05）

- 用户原话：「以后更新笔记时，按规则同步更新 OneNote 笔记，以及给噜噜的基线文件。」
- **合并单元格由用户手动在 OneNote 里做**（「合并单元格的工作留给我，我来手动合并」）。接口写不了合并，整页重写会丢掉合并。所以：
  1. 只改了文字段落的：`onenote_patch.py --docx <新基线> --sections <改动的节> --dry`，确认后去掉 `--dry` 执行；表格不动，合并保留；
  2. 改了表格的：用 `onenote_build.py --only <该节及同分区其后各节>` 重写，然后按合并清单的格式，列出这些页需要重新合并的位置交给用户；
  3. 合并清单的生成方法见交接记录第 221 轮（按页、表、行列、跨度列出）。
