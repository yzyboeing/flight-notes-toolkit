# 结构方法

## 先找主判据再展开

识别决定“后面是否还要继续判断”的核心条件。若条件 A 的某个取值会使条件 B 完全无意义，则 A 是主判据。表格用合并单元格提取主判据，次级条件在其下展开，不把叶子节点平铺成并列行。

示例只说明结构方法，不能当作用户材料补入成品：液压故障先按哪套系统失效；后缘襟翼不一致先判断是否存在不对称；起飞单发先判断机场有无一发失效应急起飞程序。

## 三层信息下沉

同一句只出现一次：

- **共性前提**：所有分支共享的入口条件、触发时机和共同限制，放表格顶部通栏行。
- **主体分支**：只放随分支变化的判断、动作和结果。
- **经验补充与通用事项**：块级例外、经验和跨类别事项，放区块末尾通栏行。

多个分支共用一整套后续动作时，把动作单独做成序号流程表，不在每个分支中重复抄写。

## 抽象分类与列语义

- A 类 / B 类 / C 类等抽象分类必须增加“参考示例”列，填具体故障、状态或场景。
- 同一列每格必须属于同一类信息。类型、现象、判据、处置、结果和说明不得混放。
- 某格混入不同语义时，移至相符的列、共性前提行或末尾补充行。

## 四类表格

| 内容类型 | 表格形态 |
|---|---|
| 故障处置类 | 故障（主判据合并列）｜类型｜现象｜处置；层级判断的“是 / 否”各占一行，现象与处置形成因果对应 |
| 对比类 | 维度少时左右两列并标共享项；每对象有 3 项以上同类维度时，对象作行、维度作列 |
| 时序流程类 | 序号｜环节｜内容；分支条件用加粗标签，PF / PM 用加粗角色前缀 |
| 分类归组类 | 类别合并列｜条目；每类用合并单元格分组 |

## 一个父条件下的多个子条件

- 原笔记已用 ①②③时，原样保留编号和顺序。
- 原笔记未编号但子条件确属同层并列时，可补 ①②③帮助定位，不得重排、合并、拆造或补写条件。
- 条件存在主次或继续判断关系时，先按主判据分层，只对同层并列项编号，不能用平铺编号掩盖层级。
- 序号优先放独立“序号”列；单元格内无法合理拆列时才保留在条件文字前。

## 章节内的知识体系顺序

- 用户要求重新梳理逻辑时，只在同一一级章节内移动已有条目，不跨一级章节。
- 顺序优先按“基础/定义 → 系统组成与正常逻辑 → 操作与限制 → 告警与失效 → 综合信息”组织；只使用原稿已有标题，不为这些分组新造标题。
- 同名章节标题从原页转成 Word 标题后只显示一次；不得再把原页的同名标题行当正文或表格重复输出。

## 单篇超过约 30 节时的块状化

仅适用于模式 A 独立文档：

- 原材料已有稳定的一级章节时，原章节名和层级优先，不另造 6–8 个主题块替换它们。
- 只有原材料缺少稳定的一级结构时，才按主题归入 6–8 个块；原有条目标题仍原样保留。
- 每块另起一页，页首使用深灰通栏块标题条；页眉右对齐显示“代号　块名”。
- 章节使用 `A-1`、`B-3` 等块内编号。
- 首页总目录表使用“块代号｜主题｜包含内容”，章节标题用“·”串联。
- 参数密集资料在总目录后增加关键数字总表，每项注明出处章节号。
- 与其他笔记重叠时，在目录下说明分工。

独立文档并入模式 B 笔记库后，块编号改为库编号，块标题降为节内小标题。
