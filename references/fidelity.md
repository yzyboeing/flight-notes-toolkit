# 内容忠实原则、主动判断与反馈

本文件优先级最高，每次任务必读。结构、排版或可读性要求与本文件冲突时，以本文件为准。

## 内容忠实原则

- **不丢失**：原始材料中的知识点、条件、动作、限制、例外、条款号和来源标识全部保留。
- **不改变含义**：只允许在同一知识点内部拆长句、去明显重复、微调语序和统一用户已经采用的术语。
- **保持顺序**：默认严格保持知识点原有先后，不借结构化或排版改变知识点顺序。
- **保留章节名称**：原稿已有的一级章节、节名和条目名原样保留，不用归纳名、简称或新分组名替换。结构化只能调整层级、顺序或合并重复内容，不得改名。
- **不自造术语**：使用原文措辞，不把原文表达换成模型自行发明的简称。
- **数值逐字保留**：速度、高度、重量、压力、温度、时间、角度等全部原样搬运，不换算、不四舍五入、不修正看似异常的值。
- **不裁决冲突**：同一知识点两处表述不一致时，两边原文全部保留，标明位置和差异，列入冲突清单。禁止取舍、平均或按“更合理”合并。
- **不猜缺失内容**：缺页、遮挡、截图重叠、图片模糊或文字不可辨时写 `【缺失，待原件补充】`。

## 主动判断与反馈

整理时主动检查，但不得擅自替用户裁决：

- **逻辑矛盾**：前后说法不一致、互斥条件并列、分支有“是”无“否”、动作顺序可能不合理。
- **疑似错误**：单位、术语、跑道号与磁航向、同一动作或门槛值在不同位置不一致。
- **表述含糊**：一句可作两解、主语不明或缺少适用条件。
- **与本次既有笔记的一致性**：同一动作、门槛值或口令在用户本次提供的其他章节出现时进行比对。遗漏的非安全关键限定条件只有来源明确时才能补回并说明依据；存在冲突时保留两边原文。
- **术语一致性**：统一为用户此前在本次文件中采用的写法，并在交付说明中列出变化。

Skill 不持有笔记状态。与既有笔记比对只能依赖本次实际提供的文件；归类或核对需要未提供章节时，明确要求用户补充。

## 外部核实边界

背景知识、系统原理、概念定义、术语标准写法或明显笔误可以使用可靠来源核实，但默认只写入“已补充 / 修正”或“存疑待证实”清单。未经用户明确同意，不把材料之外的知识写入笔记正文。

用户明确要求“只整理、不增补”时，成品正文只能来自本次提供的原始材料；不新增解释、标签、结论、来源说明或外部核实内容。外部核实若仅用于发现疑点，只放交付清单，不回填正文。

## 安全关键数据

DA/MDA、高度、速度、限制、频率、跑道数据、时间门槛和性能参数只标不改。发现可疑或与外部资料不同仍照录原文，列出差异，由用户按现行有效手册裁定。网络来源不能替代用户的现行手册。

## 交付反馈

每次交付提供：

1. 已补充 / 修正：内容、依据和来源。
2. 存疑待证实：疑问、位置和怀疑原因。
3. 冲突清单：两边位置、原文差异和需核对的原手册。
4. 待确认清单：模式 B 必须提供；模式 A 在存在机型未明、编号异常、含糊或缺失时提供。
