# 经验与教训（现行全文，2026-10-23，到 SD-231）

> **用途**：维护《B737 机型理论详解》《B737 机型理论速查》时踩过的坑，按问题类别编排。每条写「现象 → 根因 → 规则 / 做法 → 拦截」。**动手前先看对应类别**；新踩的坑当轮补进来，同时补规则正文、检查器或工具（排版规则总表 G2），让它以后被自动拦下。
> 规则正文以《规则总纲》《排版规则总表》《内容校对核心规则》为准；本文件只讲「为什么这样定、不这样会怎样」。冲突时以规则正文为准，并把本文件改正。

## 一、工作流程与协作

| 现象 | 根因 | 规则 / 做法 | 拦截 |
|---|---|---|---|
| 一轮重建 8～12 次、耗 2.5～3.5 小时 | 边说边改、每处问题都全量重建 | 用户提问题按五步处理（总纲第七节第 1 条），一轮只执行一次；自审出的问题也先全部查完、改完再统一重建（总纲第七节第 21 条） | 流程 |
| 一条全书规则波及约 150 列，用户逐页指出 8 次 | 改全书规则不看影响面 | 先用脚本列两本所有受影响的表 / 列，出 2～3 页样张，和方案一起给用户定（G3） | 流程 |
| 把全书单元格留白改成对称后，检查器多报约 80 条 T16 | 全局生成器改动没先单节预览，也没先想检查器怎么判定 | 改生成器先 `preview.py` 单节预览并跑检查；只想解决局部问题的，就只在局部生效（两表并排才用对称留白） | G3、预览 |
| 同类问题反复出现 | 只改被点名的那一处 | 把用户的例子抽象成规则，两本全书排查同类；排版要求登记《用户点名排版台账》 | K-USERPIN |
| 用户给的规则被自加阈值 / 例外（「序号靠左」加了长句条件） | 按自己理解执行 | 用户的规则按原话执行；用户定的排版规则检查器报错误，不悄悄推翻 | 流程 |
| 请用户拍板时，用户看不到方案 | 只在收尾框提问 | 先把方案正文发出来，提问只放决定本身 | 流程 |
| 同类错误连续 17 次全量重建（约 11 小时）还没磨平 | 同一类问题靠反复全量重建去磨 | 止损线：同类错误两次重建不消就停，用成品 PDF 和日志查根因，换确定性做法（总纲第七节第 18 条） | 流程 |
| 多个会话同时改、测试撞了正在用的构建 | 没先查 `git status` / `ps` | 同一时间只让一个 AI 写；会真跑构建的测试用 `sandbox.sh` 沙盒 | 开工检查 |
| 外部 AI 报告里的「笔记现文」是编的，或看串了列 | 直接采信 | 先核现文是否真实存在，再看合并格，最后回手册 | `check_adjudicated.py` |
| 已裁定的问题被反复报 | 没查裁定台账 | 先查《内容裁定台账.json》；台账里有的不再报 | `check_adjudicated.py` |

## 二、表格分页与压缩（G6 / B31 / B32 / B35）

| 现象 | 根因 | 规则 / 做法 | 拦截 |
|---|---|---|---|
| 页面里有的表 9pt、有的 7.5pt，字号参差、很难看 | 为了填上一页的空白或避免分页，把一页放得下的表也压小了（SD-223 原地收紧、方案 C、条目拉回） | SD-229：9pt 一整页放得下的表一律不压缩，放不下当前页就整表移页；只有 9pt 一整页放不下才压缩 | K-Z3 ① |
| 表压到 7.5pt，下面还空着一大截（速查第 329 页） | ① 为拉回表后注而收紧的表不参加「试退一级」；② 退级失败锁定后不再试；③ 过度压缩检查只查「9pt 能否放得下」，查不出「8pt 就够、却压到 7.5pt」 | fit_fix 每遍真排试退一级（为拉回注而收紧的表也参加），失败即锁定；锁定过的由收尾定稿退级逐张实测重试（SD-232 起不再每遍按估算解锁直退）；检查器加「退一级也放得下＝错误」 | K-Z3 ② |
| 8pt 与 7.5pt 之间跳档太大，只差一点也压到 7.5pt | 压缩级缺一档 | 4 级改为「8pt 收行距」（SHRINK_F 0.68）；检查器按表内行距区分 8pt 两档 | K-Z3 |
| 4 级「8pt 收行距」实际比 3 级矮了约 23%，又少了一档；退级时「退了会掉注」与「拉回注再压」来回跳，三次重建都退不下来 | 生成器 4 级起把格内段间距清零（原为旧 7.5pt 超大表设计）；收尾核对拿「表尾 12 字」整页找，抽字顺序不同就找不到、误判失败 | 4 级段间距减半不清零；fit_fix 收尾「定稿退级」：对仍压过头的表各退一级重排，用 check_splits 判拆表、注同页、页数不增，不满足的才恢复 | K-Z3、fit_fix |
| R5～R8 四次重建，同几张表（锂电池、MEL 放行、两型差异）反复报「压过头」，fit_fix 却说退不下来 | 检查器与 fit_fix 各算各的：检查器用固定比例估增高（4→3 级估约 13%，实测约 23%），PDF 表框把表后注也量进表高，8pt 两档的行距分界（字号 × 1.3）分不出 3、4 级；fit_fix 实测退级失败不留记录、整本多一页就整批恢复；每次只改一边的参数 | SD-232：「压过头」只有一个定义——`check_overshrink.scan_over()`，两边共用；以实测为准：fit_fix 逐张实测退一级，结果与失败原因写《压缩退级记录》，检查器读记录，实测退不下来的只提示；只因页数增加失败的逐张再试 | K-Z3、fit_fix |
| 同一个检查反复报同一处，改了几轮还在 | 修的是报错的现象，没先查「检查器和修复环节的判定是不是同一个」 | 先用同一份成品分别跑两边、比对结论；不一致就统一成一个函数、以实测为准，再改参数 | 流程 |
| fit_fix 迭代里列宽、压缩级来回跳，到第 11 遍才因「状态重复」提前停，成品取的是跳动中的某一遍 | 每遍「按估算直接退级」把锁定的表解锁再退，退了注掉页、下一遍又压回；试退成功的表之后被别处挤得拆开，压回后不加锁、下一遍又试退 | SD-232：删去每遍按估算直退；试退过又被压回的表锁定在新级别（级别最多转一次向）；锁定过的只在收尾定稿退级实测重试 | fit_fix |
| 1023R9「引气故障」表压在 8pt 又被拆到两页（R8 是 7.5pt 整表），拆表检查却报 0 | fit_fix 拿 8pt 拆开的高度按比例估「7pt 也放不下」，判成特大表；之后别处又把它恢复成压缩级，拆表处理对特大表一律跳过；check_splits 只数每截行数，不知道「压缩表不得拆开」；迭代提前停时，收尾补排排在定稿退级之后，退级用的是未验证的状态 | SD-232：已压缩的表拆开时按实测逐级升压，真排到 7pt 仍拆开才续排；特大表不带压缩级、不留试退记录；check_splits 把「压缩表被拆开」列为问题；收尾先补排再定稿退级；fit_fix 每遍留痕各表状态 | K-B1、fit_fix |
| 1023R10 迭代最后一遍实测 552 页、断表问题 0，交出去的成品却是 553 页、问题 2 | 收尾重排写的是内存状态，里面已带着最后一遍新做、没实测过的决定（列宽 ±3）；结尾又把它写回 keep_force | SD-232 ⑦：收尾以实测成品为基准，补排 / 定稿退级只改候选表的压缩级，结果逐项不许比基准差；没退成就不重排；结尾不写回内存状态 | fit_fix |
| 1023R11 第 543 页留白 406pt，下一页页顶的 4 级表按现有级别放得进；速查第 485 页压过头却「没有试过退级」 | 拉回只认「9pt 放得下」，压缩表永远拉不回；定稿退级只扫一轮，退成一张后后面的表成了新候选 | SD-232 ⑧：按现有级别实测放得进就拉回、级别不变（与 K-B5 同一口径）；定稿退级最多 3 轮、每轮重扫 | K-B5、K-Z3、fit_fix |
| 迭代总因「列宽在两种状态间来回跳」提前停，1023R12 剩下的 T13 / T8 都在这几张表上 | 加宽、收窄、借宽三种机制各记各的放弃，彼此不知道对方做过什么，相邻几遍轮流改同一列 | SD-232 ⑨：按列记净调整方向，换向两次（真来回跳）才冻结，冻结在「不做调整」的状态（冻在中间状态＝把一次掷硬币的结果定住）并记录；检查器对冻结列只提示；「试了又撤回」不冻（原有放弃记录已管） | fit_fix、K-T13、K-T8 |
| 1023R13「引气故障」表 7.5pt 被拆到两页，拆表检查报 0，fit_fix 也没处理 | check_splits 把续页最上面那一块（续表的表头行）当页眉剔掉，续表跟着被剔，断表认不出；fit_fix 用的就是它的结果 | SD-232 ⑩：落在表格里的块不算页眉；检查器有盲区时修复环节同样看不见——新增或改动检查器后在已知有问题的成品上复跑一次 | K-B1、check_splits |
| 表加了完整示例报文后被拆成 4 行 / 1 行，fit_fix 也不压缩 | 前提行被排成表外段落，fit_fix 只量表本身，以为 9pt 放得下 | 断表检测量不准的表在源文件定级 `fit-N`（G6 ⑤）；检查器跳过 `fit-N` 表 | K-B1 |
| 表格拆开后整体性很差、排版乱 | SD-218 允许表格任意跨页、每截 1 行 | SD-223 / 229：一页放得下（含压缩到 7pt）的表整表同页；只有特大表续排，每截 ≥ 3 行、续页重复表头 | K-B1 |
| 拆表强制记录在同一次构建里只加不撤，节末留下半空页 | fit_fix 早先的判断后来过时了 | 每遍复查强制拆开、整表移页，过时的撤销；分页类记录只在本次运行内有效 | fit_fix |
| 表后注单独掉到下一页 | 注没有跟表一起移页 | 表后注跟表走：表＋注一页放得下就整体移页 | K-B4 |
| 留白页：上一页空着大半，下一张表却在下一页 | 早先整表移页时页面还没排定，后来空出了位置 | 被移到页顶的表每遍复查：上一页空位 9pt 放得下（连表后注）就拉回 | K-B5 |
| 两表并排的组被拆到两页 | 外层组合表的行允许跨页 | 并排组整组不拆页（`cantSplit`） | K-B1、目视 |
| 每次全量重建都有一处表格下移 / 留白换位置出现（R3～R6 来回跳） | 下移记录 B: / SB: 每次冷启动重算；fit_fix 拉回与 check_gaps 判「放得下」口径不一（R6 差 0.03pt） | 两边共用一个判据函数、收尾加 B5 归零；没治理前不靠反复全量重建碰运气（SD-235 收尾） | K-B5 |

## 三、列宽、对齐与加点（B26 / B27 / B38 / B42）

| 现象 | 根因 | 规则 / 做法 | 拦截 |
|---|---|---|---|
| 按「列右侧空白」收窄后，表反而被压到更小（速查第 329 页图上标注） | 空白是在压缩字号（7.5pt）下量的，按它收窄后，字号一恢复就折行，fit_fix 只好压得更小 | **列宽只在 9pt 下量**；压缩表的空白换算回 9pt 再定，拿不准就不写定宽（B26） | 流程 |
| 两列宽度明显反了（文字少的列 60%、文字多的列 31%） | 表头手工 `w-` 比例写错，又没复核 | 改 `w-` 后看成品；比例按两列最长一行实测 | K-T13 / T14 |
| 列宽空白每轮剩 20～30 处，来回跳 | fit_fix 在两种列宽状态间震荡 | 收不拢的列按 9pt 实测写定宽；不靠反复重建去磨（止损线） | K-T13 / T14 |
| 估算列宽和实测不一致，检查与修复各说各的 | 用字符数估算 | 以 PDF 实测为准（`layout_measure.measure()` 检查器和 fit_fix 共用）；「；」后有意换行不算折行 | 检查器 |
| 用户点名居中的列下一版又带了圆点 | 只改了成品，没有登记 | 点名的列在表头显式标注，登记《用户点名排版台账.json》 | K-USERPIN |
| 一张表里一列居中长句、旁边一列靠左加点，很乱 | 自动规则各管一列 | 同表统一：已有加点列时，长句单项列也加点（B38） | K-T6 / T7 |
| 短值列（高度上限、遭遇时机、等级范围）带小圆点 | 一格两三项短值也被当成多项加点 | 三列以上表的短值列整列居中不加点（B42）；两列表仍按 B10 ② | K-USERPIN |
| 窄列居中的字偏右，检查器判「没居中」 | 单元格左留白 170、右留白 90，本来就不对称 | 两表并排里的居中格左右留白对称；全书其他表不动 | K-USERPIN |
| 首列锁了 12% 宽，成品却是 18%（完整版 4.3「环节」） | 生成器只对「满宽锁宽」的表跳过旧借宽记录（BW），单列锁宽的列照样被借宽撑大 | 表头标 `w-lock` 的列不借入、不借出；改锁宽时清该表旧 W / NW / BW 记录 | K-T13 |
| 灯名首列出孤字、多占行 | 「灯名（颜色）」挤在一行 | 说明格本来就占两行以上时，颜色另起一行（B41） | 人工 |

## 四、注、缩写与内容写法（B37 / W06 / content-core）

| 现象 | 根因 | 规则 / 做法 | 拦截 |
|---|---|---|---|
| 「注 ｜ 说明」注表大多和主表分在两页（两本 61 张） | SD-209 把 ≥ 4 条注改成了独立注表，注表不跟主表走 | 注一律写注行、紧跟主表（B37）；能并回表格行的并回 | K-T32 |
| 注表改注行后，有的速查条目一张表也没有了 | 这条的全部内容本来就是那张注表 | 改之前先查：整条只有这张表的，改成「项目 ｜ 说明」正表 | K-T38 |
| 用户问「PDG / OIS / TCH / RDH / LOUT 是什么意思」 | 缩写注只放主场条目，表头、标题里的缩写被当成顺带提到 | 标题、表头、首列、要点里出现的缩写，这一条就是主场，必须注（W06） | K-T35、`abbr_home.py` |
| 加缩写注时重复了（已有「英文全称——」注） | 只按「缩写：英文」一种写法查重 | 查重要覆盖「英文全称——」注、表头括注、「缩写（English）」 | 人工 |
| 示例报文写「全文从略」，解读没法对照 | 示例只给了报头 | 示例先写全原文、再逐段解读（content-core 第五节） | 人工 |
| 精简后丢了数值（高度表 75ft） | 改写前没列全原文要素 | 精简 / 改写前列全数值、条件、例外、机型，改后逐项核对，附无损声明 | 流程 |
| 「内容丢失」误报 | 用整句 grep，`<em>` 把句子切断了 | 用去标签的短片段再查 | 流程 |
| 重编号后按条号找不到内容 | 按页码 / 旧条号定位 | 先按内容定位 | 流程 |
| 正则改号误伤「PDG 3.3%」「SOP 1.3」 | 用了黑名单匹配 | 改号用白名单（`move_items.py`） | 工具 |
| 用自造说法转述手册（「结冰偏置」） | 没用原句 | 用 FCOM / FCTM 原句；禁用说法进《手册用语表》 | K-W13 |
| 补行时整表替换，通用表头误配、丢了行 | 整表替换 | 补入只逐行合并；补完跑丢失 / 重复扫描 | K-S7 |
| 新加的知识点和已有内容重复 | 没先通查 | 新增前先检索两本同一数值、术语、缩写、主题，能并入优先并入 | 流程 |
| 手册查不到的内容被删或被标注 | 当成「无出处」 | 查不到＝培训资料，不删、不标注、不上报（SD-94） | 流程 |
| 速查删条目后检查器报「原有表行丢失」，构建白跑一轮 | 删行没登记 | 删条目先列清单让用户确认，并登记《速查删行台账.json》；删条目后同步两份主题索引 | K-S7、check_src |

## 五、插图（P01～P07）

| 现象 | 根因 | 规则 / 做法 | 拦截 |
|---|---|---|---|
| 用户要求移到表前的图被放大，和标题一起挤到下一页 | fit_fix 按下方空白放大图，不知道位置是用户指定的 | 用户点名移位或缩小的图，图行标「定」锁宽（P06） | 目视 |

| 图注写了手册出处 | 旧规则 | 图注只写「图号　标题」（P04） | K-S1 |

## 六、构建、工具链与源文件
