# 内容校对核心规则（唯一口径，2026-10-05；2026-10-19 更新到 SD-209）

> 任何 AI（Claude、噜噜或其他）核对《B737 机型理论知识笔记》内容时都按本文件执行。
> 工具与流程各看各的：Claude 用《AI校对指令_通用.md》，噜噜用当期 M 指令；两边的口径冲突时以本文件为准。
> 已裁定过的问题在《内容裁定台账.json》里，**台账里有的不要再报**；复核方会先按台账过滤。

## 一、三条铁律

1. **宁可漏报，不可错报。** 核过没问题就记「核对无误」，不按条数评价工作。编造一条（现文搜不到、手册页码对不上、排版问题成品页上不存在），所在部分整个退回重做；「核对无误」也会被抽查 10%。
2. **逐字引文＋精确定位。** 「笔记现文」从基线逐字复制（含标点、【】、•、–），不改写、不拼接、不省略；写页码＋条目号＋位置；报出前用引文在基线 PDF 里回查一遍。手册依据写全：手册名、修订号、章节号、原 PDF 页码＋一两句原文摘录；没有手册原文的内容问题和补全建议一律不收。
3. **查不到 ＝ 培训资料，不是问题（SD-94）。** 手册里找不到依据的内容默认来自公司培训课件：不报「无出处」、不建议删除或按手册改写，只审逻辑和表达（改法写「改为……（意思不变）」），台账标「手册无依据（培训资料）」。存疑只给「查到了手册但两处说法拿不准」的情况，全书 ≤ 40 条。

## 二、核对一个知识点

- **逐项核**：逻辑（条件与结果、先后、任一/全部、且/或、必须/建议/可以、适用阶段与机型）；数值与边界（数值、单位、范围端点、含不含本数）；限定条件（前提、例外、适用范围有无扩大缩小）；表达（概括有没有把「建议」说成「必须」、「可能」说成「会」）。
- **同一主题查全**：FCOM、FCTM、QRH、AFM、SOP、运行手册、MEL、除冰大纲、技术通告都查；检查单看全所有分支。手册之间说法不同报「手册口径不一」并列各家原文，不直接说笔记错。
- **两型分开核**：737-NG、737-8 各用各的手册；不默认两型相同，也不拿一型手册说另一型错。
- **先判合并格**：读 Word 必须处理 gridSpan / vMerge；要报「空白」「错列」的先看成品页图像（M15、M16 的错报全是合并格误读）。
- **全书查一致**：同一数值 / 术语在全书其他位置（第 1 章原理 ↔ 第 4 章处置 ↔ 第 5 章提示）是否一致；改一处列出全部联动位置（SD-109）。

## 三、既定口径

- 中文「以上 / 以下」含本数；英文 more than / less than 以英文为准。
- 记忆项目以 QRH 原页**虚线**为界；「■■■■」是分支结束标记，不是记忆项目分界。
- 「未入库」先查《手册版本清单》再说（M17 教训：60 条「未入库」其实都在库里）。
- 全书不写来源 / 出处（SD-138）、不写「详见」和表内交叉引用（SD-137 / SD-140）；发现残留按「写法」类报。
- 依据权威顺序：局方规章 ＞ 公司与波音手册 ＞ 部门资料；AOP、安全案例集、课件不作核对依据，但部门资料查全再下结论。
- 书内机型统一称 737-NG / 737-8。
- **两本成品**：完整版（正文第 1～5 章，唯一内容真源）＋ 速查版（独立成册，`速查/速查源.md`，SD-146 / 163）。旧第零章速查区与「速查 N」老编号作废（SD-139）；速查以正文为准，新知识点先进正文，再精简进速查，改正文要同步速查（SD-109）。
- **速查只放数据和概念（SD-168）**：不放逐步程序（《基础数据》里有的程序类保留）、不放算例（报文编码格式列不算算例）；以旧版《基础数据》为知识点参照，数值以现行完整版为准。
- **两本都不收 HUD / AIII 内容**（SD-168）。
- **两型共有的概念 / 知识点用左右对比表（SD-170，2026-10-09 用户：「凡涉及两个机型共有的概念或者知识点的时候最后用表格分类左右对比整理」）**：两型都有的概念或知识点，整理成「项目 ｜ 737-NG ｜ 737-8」左右对比表，按项目分类分行；两型相同的格跨两列合并写一次（共有格居中，SD-156）；不在格内或段落里用「【737-NG】…／【737-8】…」混写。只有一型有的内容仍用【机型】标签。两种排法按知识点类型选（2026-10-09 用户定）：**排法一**——指示灯、限制、条件清单这类（一行一个项目），排成「项目 ｜ 两型相同 ｜ 仅 737-NG ｜ 仅 737-8」四列，共同部分只写一次；**两型没有差异的行，「两型相同」格跨满三列，不写「—」**（只有一型有内容时另一型写「—」）；两型名称不同的在首列写「名称（737-NG）／名称（737-8）」；**排法二**——系统原理、控制逻辑、失效处置这类（两型做法不同），排成「项目 ｜ 737-NG ｜ 737-8」，两型相同的行跨两列合并。不用「左格写全、右格只写新增」（右格会被误解为继承左格全部内容）。
- **用户定的写法以《内容裁定台账》为准**：即使与手册原文不完全一致，台账里有就不再报；用户新改动与手册不一致时，先摆出原文让用户定。

## 四、补全、精简与展示

- **补全**写清三点：补什么（建议文字）、补到哪里（块 / 表行 / 表后注）、为什么重要；不为补而补——背景介绍、与操作判断无关的原理细节不补；大参考表不照搬，写定义与查法（规则 F10）。
- **精简信息无损（最重要）**：数值、单位、条件、例外、机型标注、颜色一个不丢；每条精简附「无损声明」（列出改前每个数值条件 → 写明改后位置）。手册原话（检查单、警告、限制、定义）不精简，只能报排版。
- **不算啰嗦**：两型对照里两列相同的写法、缩写 / 口诀说明、安全警示的重复。
- **原理类定义不写公式**（SD-152，2026-10-06 用户，2.8 第 1 条 空速）：用浅显的话写清每个概念的含义、与相关概念的关系，必要时加一条「关系」注；公式与推导不写。
- **并列多条用表**（SD-152，2.8 第 3 条；SD-173 扩大到全书）：并列的因素、情况、位置含义、条件、分支、状态等写成表格，不写成一串 ①②③ 文字；「满足以下任一条件」作表头或前提行；只有一句话的定义不改。用户原话：「能用表格表达以让条例更清晰的建议都用表格」。
- **速查版内容口径（SD-174）**：以正文原表为准；一型独有的条目归 09 差异页；不写纯英文全称的注；只排目视参考图。
- **展示方式**按语义判断（限制 / 数值 / 步骤 / 对比 / 因果 / 定义各有合适排法），建议改排法时列全书同类 ≥ 2 处作对照，且不违反《排版规则总表》。

## 五、两本一致与结构（SD-191 / 192，2026-10-16 用户：「速查版和完整版相同的内容保持一致，我说改一处那另外一处也要统一」）

- **共有内容两本一致**：同一知识点在完整版和速查里的数值、条件、术语、表结构、行写法一致，以速查优化过的为准；完整版独有的行和更详细的文字保留（不算不一致），速查精简时删掉的半句不丢（完整版格内或注）；完整版较新且更准确的（两型对比表、补了一型信息的）反向同步速查。报问题时两本位置都写（完整版块号 + 速查条目号），改法两本都给。
- **删改一律两本同做**：删除、改写、移注、拆合表，两本同改，不提「完整版保留」作选项；删除前把被删一边独有的信息并到保留的一边，写明并到哪里。
- **合并后查重复**：一行或一张表换成另一本的写法后，查同块里有没有表内表外重复的句子（速查常把正文的表后注并进格内）。
- **同一本里的重复**：相邻条目 / 不同章节讲同一件事、文字大段重合的（如 1.14 防滞原理与 1.14 第 13 条），保留一处，独有信息并入，另一处删；只是互补（原理 ↔ 处置 ↔ 模拟机程序）的不算重复。
- **主题目录归属与顺序**：每个块至少挂一个主题；挂得牵强的、该挂没挂的、主题内顺序不合逻辑的（「按系统」本节块按正文序在前，其余按章节号；阶段主题按飞行流程）都按「一致性」报，写出改前 → 改后。
- **表里只放主值**：表格结构说明、查表方法（「先选表再查速度」）、与标题不符的引语，不放在标题和表之间；与表重复的注删。
- **两型表述统一**：两本对同一两型差异的写法（对比表 / 【机型】标签）一致，按 SD-170 选排法。

## 六、问题分类与级别

- **类别**：内容 / 逻辑 / 补全 / 优化 / 精简 / 展示 / 一致性 / 写法。
- **级别**：A 与手册矛盾或可能误导操作；B 不准确、不完整或逻辑有问题；C 全书不一致或删后丢信息；D 表达优化、精简、展示、写法。
- **改法**写成可直接执行的形式；精简附无损声明；联动位置列全，没有写「无」。

- **表述贴近原手册（SD-177，2026-10-11 用户）**：译名与句子尽量用 FCOM / FCTM 中文原文（其次 QRH、公司手册）；原文明显逻辑错误或过于繁琐不明了时才改写，改写不改原意、数值与条件逐字。

## 七、两本定位与内容结构（SD-209，2026-10-19 用户通过整体优化方案）

**Q00 两本定位表**

| 维度 | 完整版 | 速查 |
|---|---|---|
| 目的 | 系统理解：原理、逻辑、程序全貌、两型差异 | 快速查数与判断：数据、限制、条件分支、门槛 |
| 组织 | 节 = FCOM 章 / 手册；条目按 N1 顺序 | 段 = 飞行流程；组 = 系统 / 主题；条目按正文序，同一知识链的条目相邻、可不按正文序（1019R6 记录第 60 条） |
| 一条的样子 | 不限长；表 + 注 + 图 | ≤ 1 页；首行「要点」一句话；以表为主；注 ≤ 3 |
| 程序类 | 完整步骤 | 只收门槛、分支、口令 |
| 算例 | 可写 | 「例：」注 ≤ 1 条 |
| 图 | 系统原理图、逻辑图 | 判读图（仪表指示、数据表） |
| 入口 | 目录 + 5 维主题目录 | 8 段 + 按主题查 + 必背清单 + 限制数据总表 + 缩写表 |
| 一致性 | 共有表以速查为准（Q04） | 同 |

**N 组结构规则**：N1 节内顺序（系统类：组成与原理 → 控制与正常工作 → 数据与限制 → 指示与告警 → 非正常与处置 → 技术提示；运行类：定义与概念 → 规则与标准 → 按飞行阶段的程序 → 非正常 / 特殊情况 → 案例与算例）；N2 一节 5～25 条（第一章只查下限）；N3 同一系统的原理与技术提示放同一节，第五章只留跨系统专题；N4 一条目注 ≤ 3（≥ 4 改注表或并回表格，B37）；N5 条目分级 `{★★}` 必背 / `{★}` 必会 / 无星了解。核对时「顺序不合 N1」「同主题跨章」「注过密」按「一致性」类报，写出改前 → 改后。

**速查内容口径修订（Q03）**：速查 = 数据 + 限制 + 概念 + 判断分支与关键门槛；程序类只收门槛 / 分支 / 口令表；算例以「例：」注收、一条目 ≤ 1 条；旧 SD-168「不放程序、不放算例」按此修订。

## 1019R6 补充（优化意见记录第 32、51、53、54、60、81 条）

- **随通告更新的名单不抄进笔记（第 32 / 39 条）**：机场 / 跑道 / 程序名单（不得继续进近的降水机场、不执行单发滑行机场、慢车除冰机场等）只写查询位置（手册 › 章 › 节）。
- **两本一一对应（第 51 / 55 条，用户：「内容分布和查询逻辑不一样，但是知识点是一一对应的」）**：速查每个知识点都能在完整版找到出处（绑定写全）；两本都有的，数值、条件、结论必须一致，速查只许少收行、不许改写成不同意思；改一处必须同改另一处。
- **精简口径（第 53 条）**：手册原句（限制、警告、程序步骤、CAUTION / NOTE）不改写，只删重复；培训性解释、推理、导语里的拖沓句与同一条里说两遍的内容可以精简；精简前列全原文要素（数值、条件、例外），改后逐项核对。
- **速查一个知识点只写一处（第 54 条）**：不同主题相同的知识点只留查找时第一反应的那条，另一主题在《速查按主题查》用 see 挂接；机型差异段与限制数据总表保留汇总式重复。
- **速查相关知识点放在一起（第 60 条）**：同一知识链的条目归入同一主题、前后相邻（是什么 → 怎么触发 → 怎么处置）；8 段划分与段序不动。
- **第五章并入前四章（第 81 条）**：原第五章技术提示 5.1～5.8 已按相关性并入 1.1、2.1、2.8、3.3、3.6、3.9、3.14 节末「技术提示」小标题；全书四章，「跨一级章节不移动、不归并」对原第五章开过一次例外。
- **引用程序只写名字（用户 2026-10-20：「直接写完成地形改出机动飞行，不用写具体章节」「同类的问题也是一样，只写出相关程序的名字不用写具体章节」）**：正文、注、表格里提到程序 / 检查单 / 机动 / 手册条款时只写名字（如「完成地形改出机动飞行」「转阅《紧急下降》检查单」「按 FCOM 补充程序「低温高度修正」」「SOP 写作…」），不写本书章节号（x.y 第 N 条）、QRH 页码、FCOM / FCTM / SOP / 运行手册的章节编号；例外：随通告更新的名单写查询位置（第 32 条，章节路径就是要查的内容）。图注同样不写手册出处（SD-212，用户 2026-10-20：「图注里的手册出处都去掉，按『引用只写名字』的原则统一处理」）——去掉 FCOM / FCTM 章节、AC 图号、技术提示汇总与「依据本条」，括号里只留适用机型、「示意」「培训示意图，仅供参考」等性质说明和图内说明。
