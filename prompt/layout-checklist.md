# 排版校对规则总表与检查清单（SD-79 / SD-102 / SD-103，2026-10-01 更新）

> 用户原话：「把目前所汇总的排版要求以及我们总结的整理规则，做成一个检查器或者清单。不要再让我人工发现问题并反馈给你，而是每次能直接扫一遍……任何 AI 只要使用这个检查器，都可以去发现不符合要求的地方。」

## 怎么用（任何 AI 通用）

1. 改完笔记或工具链后，先出成品：
   ```
   cd ~/flight-repos/gh-private && ./sync.sh --full --no-push "说明"
   ```
   sync 结束时会自动跑检查器，报告写到 `build/排版检查报告.md`。
2. 也可以单独跑检查器：
   ```
   python3 ~/flight-repos/pub/tools/check_layout.py --out ~/flight-repos/gh-private/build/排版检查报告.md
   ```
3. 按报告处理：
   - **错误**：违反已定规则，必须改到 0。
   - **建议**：可能需要优化。逐条打开成品 PDF 对应页看，按下面「判定标准」裁定：要么改，要么在交接记录里写明「不改，理由……」。不能整批忽略。
4. 第一部分「排版校对规则总表」是判定标准；第二部分是检查器规则号；第三部分是机器判不了、要看成品页的语义项。
5. 人工或外部 AI（如 Muse）校对时，按第一部分逐条对照成品页；每条问题写明页码、条目号、表头和违反的规则编号（如 A3、B1）。
6. 改源文件前先备份，不删文件，只在本地提交。数值、限制和程序只以本地手册库为准，见 `AI校对指令_通用.md`。

## 一、排版校对规则总表

> 规则编号供校对时引用。「自动」＝生成器 build_docx.js 已执行，写源文件时不用手动处理；「检查」＝检查器 check_layout.py 会报；「人工」＝要看成品页判断。用户的点名意见优先于自动规则，用表头显式标注（第 E 组）落实。

### A　对齐：什么居中、什么靠左

| 编号 | 规则 | 执行 |
|---|---|---|

| A2 | 首列是项目名 / 标签时整列居中加粗；判断长短前先去掉括注。首列是完整句子的不算标签，左对齐。 | 自动 |
| A3 | **数字和字少的格子居中，不靠左加点**（SD-103）：数值、带单位的值、短值、短语（如「230kt」「不提供」「2900～3600psi」「离地 35ft → 起落架收上」）。一列都是这类内容时整列居中。 | 自动 / 检查 T3 |
| A4 | 每格都是一句短话（约 20 字以内、没有句读）或顿号分隔的短词列举的列，整列居中。 | 自动 / 检查 T3 |
| A5 | 非首列表头为「时机 / 宣布时机 / 总则 / 类别」的列整列居中，格子是长句也居中。 | 自动 |

| A7 | 序号表（首列全是 ①② / 1、2）其余列有约 8 字以上的格就整列左对齐；只有数字或短值的列不受影响。 | 自动 |
| A8 | 「—」占位居中；所有格子纵向居中。 | 自动 |
| A9 | 个别格要居中（如两型共用的跨列条件格）用 `<td class="center">`。 | 显式 |

| 编号 | 规则 | 执行 |

| B2 | **「说明」列可以加点**：表头以「说明」结尾的列，短说明（约 6 字以上或带句读）也算句子，整列左对齐加点。 | 自动 / 检查 T11 |
| B3 | 取值列不加点（同 A3）：B1 的门槛达不到的列，一律按 A3 / A4 居中。 | 自动 |
| B4 | **序号表不加点**：首列是序号的表，序号已经编了项，其余列不自动加「•」。用户点名要加的在表头标 `col-bullet`（速查第 40、61 条，正文 1.13 B-5、1.2 C-1）。 | 自动 / 检查 T12 |
| B5 | 一格内有两个以上各自独立的判断、条件或动作才分条；短状态、标签、带因果或转折的连续叙述（但 / 因此 / 即 / 其中 / 否则 / 而 / 且 / 或……）不分条；整格约 35 字以上才按「；」拆。 | 自动 / 检查 T4 |
| B6 | **同列加点统一**：一列里有格子加了「•」，同列其他句子格也加；取值列的短值和 ①② 步骤格除外。 | 自动 / 检查 T6 |
| B7 | **引语 + 子项**：以「：」结尾的引语排「• 引语：」，后面的并列项排「– 子项」，子项到第一个以「。」结尾的那条为止；整格每段都以「- 」开头的是并列列表，排「•」，不排短线。 | 自动 / 检查 T10 |

## 三、机器判不了、每轮要看成品页的语义项

T2～T4、T11 和 L5 报出的只是候选；裁定标准见第一部分，下面是补充。

1. **格内分条看语义**：B5 判不准时，看一格里是不是有两个以上各自独立的判断、条件或动作；短状态、标签、带因果或转折的连续叙述不拆。整列加点（B1 / B2）与格内分条是两回事：整列加点时一格只有一句也加一个「•」。
2. **居中看信息职责，不只看字数**（SD-75 / SD-103）：数字、短值、短语、单句短话居中；段落、列举、例外、因果展开左对齐；「条件」列看内容——是短的分界 / 取值就居中（如起飞阶段「离地 35ft → 起落架收上」），是句子就按 B1 加点。
3. **颜色只由显式标记决定**（SD-75 / SD-98）：不因为是数字就标蓝，不整句标红；同一列含义相同的数同色，速查与正文同值同色。
4. **黄色底**：只标需要特别注意的那一两格（`<td class="hl">`），整行黄底只留给警示通栏行（SD-99）。
5. **层级符号**「• 引语：」+「– 子项」只用于引语后接两条以上平行条件（B7）。
6. **表后的注、解释、出处紧跟表格同页**。同一条目的两张表跨页、表后说明段跨页属正常，不算 B 类错误。
7. **一页放得下的表整表移到下一页，上一页因此留白**，这是 SD-71 的既定代价，不算问题。
8. **源文件**：行首不写项目符号（符号只由渲染器加），`<br>` 主动分行不要滥用，机型标签用全角【737-NG】【737-8】（SD-11）。

## 四、每轮收工前

- **速查区改了，后续章节一并改**（SD-92）：速查区做任何更改或优化，都必须检索第 1～5 章里对应的内容，包括「详见」指向的条目和出现同一数值、同一术语的其他位置，一并修改；改排版标注的，正文同表也要标（S5）。sync 前会自动运行 `quickref_sync_hint.py` 列出要核对的位置。

- 检查器错误 = 0；建议逐条有结论（改了，或写明不改的理由）。
- 在 `00_先读我_AI交接.md`「每轮工作记录」顶部写本轮记录，记下报告里的错误数和建议数。
