# 排版与整理规则检查清单（SD-79，2026-09-30 用户）

> 用户原话：「把目前所汇总的排版要求以及我们总结的整理规则，做成一个检查器或者清单。不要再让我人工发现问题并反馈给你，而是每次能直接扫一遍……任何 AI 只要使用这个检查器，都可以去发现不符合要求的地方。」

## 怎么用（任何 AI 通用）

1. 改完笔记或工具链后，先出成品：
   ```
   cd ~/flight-repos/gh-private && ./sync.sh --full --no-push "说明"
   ```
   sync 结束时会自动跑检查器，报告写到 `build/排版检查报告.md`。
2. 也可以单独跑检查器：
   ```
   python3 ~/flight-repos/pub/tools/check_layout.py --out ~/flight-repos/gh-private/build/排版检查报告.md
   ```
3. 按报告处理：
   - **错误**：违反已定规则，必须改到 0。
   - **建议**：可能需要优化。逐条打开成品 PDF 对应页看，按下面「判定标准」裁定：要么改，要么在交接记录里写明「不改，理由……」。不能整批忽略。
4. 下面第二部分是机器判不了的语义项，每轮也要按清单抽查成品页。
5. 改源文件前先备份，不删文件，只在本地提交。数值、限制和程序只以本地手册库为准，见 `AI校对指令_通用.md`。

「一页放得下不拆」的实现：`sync.sh` 调用 `fit_fix.py` 两遍排版。第一遍按估算高度绑定。然后把 PDF 实测「断开但放得下」的表记进 `build/keep_force_<成品名>.txt`，第二遍强制整表同页。清单跨次保留；表格改动后签名对不上会自动撤出。

**略超一页的表**（SD-80，2026-09-30 用户批准：「最小 8pt、仅限略超一页的表」）：连同条目标题不超过 1.2 页、且不是跨 3 页以上的大表，由 fit_fix 按 PDF 实测逐级压缩，放下即停。
- 1 级：9pt 不变，收紧行距与单元格边距。
- 2 级：8.5pt。
- 3 级：8pt，这是底线。

8pt 仍放不下的，照常行间分页，同时守防孤行规则。更大的表不缩字。

## 二、机器判不了、每轮要看成品页的语义项

T2～T4 和 L5 报出的只是候选，下面的标准同时也是裁定这些建议的依据。

1. **加点（•）只给长的、并列的语义句**（SD-78，用户：「加点只限于长的、并列的语义的句子」「要结合语义去判断是否有多个并列的语义」）。
   - 一格里有两个以上各自独立的判断、条件或动作，才分条加「•」。
   - 短状态（如「ALTN 电门亮」）、标签格、带因果或转折的连续叙述（但 / 因此 / 即 / 其中 / 否则……）不加点。
   - 「引语：子项；子项」写成引语一行，下面列「–」子项。
   - 真正的时序步骤用 ①②③，不与「•」混用。
2. **居中看信息职责，不只看字数**（SD-75）。单一紧凑短句的列（原理 / 状态 / 现象 / 结果……）整列居中。段落、列举、例外、因果展开左对齐。「条件」列要看内容，不能机械地左对齐或居中。
3. **颜色只由显式标记决定**（SD-75）：`<em>` 红色表示边界、警戒、硬性动作；`<b>` 亮蓝表示记忆值；`<strong>` 表示一般黑粗。不因为是数字就标蓝，不整句标红。
4. **黄色底只用于** `class="priority"` / `class="warn"` 的整行最高优先级（SD-75）。
5. **层级符号**「▪ 主题 / – 子项」只用于「短主题：」后接两条以上平行条件（SD-75）。
6. **表后的注、解释、出处紧跟表格同页**。同一条目的两张表跨页、表后说明段跨页属正常，不算 B 类错误。
7. **一页放得下的表整表移到下一页，上一页因此留白**，这是 SD-71 的既定代价，不算问题。
8. **源文件**：行首不写项目符号（符号只由渲染器加），`<br>` 主动分行不要滥用，机型标签用全角【737-NG】【737-8】（SD-11）。
9. **内容规则**不在本清单，见 `AI校对指令_通用.md`：数值原样照录、两型不默认相同、只以本地手册库为据。

## 三、每轮收工前

- 检查器错误 = 0；建议逐条有结论（改了，或写明不改的理由）。
- 在 `00_先读我_AI交接.md`「每轮工作记录」顶部写本轮记录，记下报告里的错误数和建议数。
- 用户新提出的排版要求，先加进本清单和 `check_layout.py`，再改成品。只改成品不加规则，同样的问题还会再出现。
