# 排版与整理规则检查清单（SD-79，2026-09-30 用户）

> 用户原话：「把目前所汇总的排版要求以及我们总结的整理规则，做成一个检查器或者清单。不要再让我人工发现问题并反馈给你，而是每次能直接扫一遍……任何 AI 只要使用这个检查器，都可以去发现不符合要求的地方。」

## 怎么用（任何 AI 通用）

1. 改完笔记或工具链后，先出成品：
   ```
   cd ~/flight-repos/gh-private && ./sync.sh --full --no-push "说明"
   ```
   sync 结束时会自动跑检查器，报告写到 `build/排版检查报告.md`。
2. 也可以单独跑检查器：
   ```
   python3 ~/flight-repos/pub/tools/check_layout.py --out ~/flight-repos/gh-private/build/排版检查报告.md
   ```
3. 按报告处理：
   - **错误**：违反已定规则，必须改到 0。
   - **建议**：可能需要优化。逐条打开成品 PDF 对应页看，按下面「判定标准」裁定：要么改，要么在交接记录里写明「不改，理由……」。不能整批忽略。
4. 下面第二部分是机器判不了的语义项，每轮也要按清单抽查成品页。
5. 改源文件前先备份，不删文件，只在本地提交。数值、限制和程序只以本地手册库为准，见 `AI校对指令_通用.md`。

- 3 级：8pt，这是底线。

## 一之二、同列统一规则（SD-83 / SD-84，2026-09-30 用户对速查第 15～55 条的反馈）

生成器会自动执行下面这些规则，检查器用 T3、T6、T7、T8 报出漏网的地方。

1. **同列加点统一**（第 15、16 条）：一列里只要有格子分条加「•」，同列其他句子格（包括「中断起飞。」这种带句号的短句）也加「•」，整格作一项。
   - 源文件里用「- 」写的子项，统一排成「• 引语 + – 子项」。
   - 取值列不强求统一：同列里有「持续」「V2」「≥ 800m」这类短值时，只给长的并列格加点，短值居中不加点（第 52 条）。
2. **什么时候不加点**：
   - 「定义 / 含义 / 释义 / 概念」列，一格就是一个完整概念，不拆；短定义整列居中（第 23 条），两行以上的段落式定义整列左对齐（2026-09-30 M3 复核定，第 025 / 027 条）；
   - 两句短要求不拆（第 34 条），整格约 35 字以上才按「；」拆分；
   - 短语、单个词不加点，居中（第 52 条「触发条件」「坡度指针 / 侧滑指示」）。
3. **引语加子项**（第 54 条）：首段以「：」结尾、后面接两段以上的，首段加「•」，后面各段作「–」子项。
   - 格里只有一句「引语：子项；子项」时，引语同样加「•」、子项「–」（SD-93「一律」，M3 第 018 / 021 条）。
   - 并列的备选条件（「满足以下任一：」后面的各项）不编 ①②，写成子项；①②③ 只留给真正的时序步骤（M3 第 002 / 005 / 015 条）。
4. **单句列、短词列居中**：
   - 一列（首列也算）每格都是一句话（句中没有句号）、约 40 字以内、没有分条，整列居中（第 24 条「渗漏场景」、第 25 条「动作」）；
   - 顿号分隔的短词列举不论多长都居中（第 50 条「触发音响」）。
5. **末行孤字**（第 55 条）：格子折行后末行只剩一两个字，或者短标签被折断的，从最宽的列匀出宽度，让它少折一行或排成一行。
   - 生成器先按估算加宽；
   - `fit_fix.py` 再按 PDF 实测补宽（SD-85，`layout_measure.py`）；
   - 仍放不下的由检查器 T8 报出，人工裁定。
6. **连写的步骤每步一行**：一格里「（引语：）① …；② …；③ …」连写的，引语一行，每步另起一行悬挂对齐。「① … → ② …」箭头串联的是顺序链，保持一行。
7. **两型对照表两列格式一致**：「737-NG / 737-8」并排对照的两列，同一行的格子要按同一规则排（都加点或都不加点）。自动判断不一致时，两列表头都标 `col-bullet` 或 `col-plain`。
8. **近乎空白的页**：
   - 节标题、「块索引」小标题或条目标题独占一页、表格在下一页的，块索引表改为允许按块的边界分页（续页至少 2 块，不重复表头，符合 SD-29）；其他表缩小一级，让标题与表同页。
   - 表后说明被挤到下一页、单独占一页的，作为已知情况登记。
   - 以上由 fit_fix.py 实测后自动处理（SD-87）。
9. **序号表其余列左对齐**（SD-90）：首列是 ①②③ 或 1、2、3 的表，其余列按清单左对齐；数字或短值列、表头标 col-center 的列不受影响。
10. **显式标注**（语义判断的最终手段）：自动规则判不准时，在源文件表头上标注，并在变更记录里写明理由。
   - `<th class="col-center">`：整列居中、不分条（第 49、51、52、55 条）；
   - `<th class="col-bullet">`：整列每格加「•」（第 24 条「现象 / 结果」、第 52 条「其他说明」）；
   - `<th class="col-left">`：整列左对齐；
   - `<th class="col-plain">`：整列不分条、不统一加点，对齐照常（两型对照表里合并格多的用这个）。

   速查区与正文里的同一张表要标成一样。

## 一之三、句子列加点、时机列居中、序号表不加点（SD-102，2026-10-01）

- 非首列「说明 / 条件 / 限制 / 定义 / 处置……」类表头、六成以上是句子的列，生成器自动整列左对齐加「•」（一格一句也加）；全是短语 / 取值的列不加。
- 非首列「时机 / 宣布时机 / 总则 / 类别」列整列居中。
- 序号表（首列全是 ①② / 1、2）其余列不自动加点；用户点名的在表头标 `col-bullet`。
- 单格居中：`<td class="center">`。

## 二、机器判不了、每轮要看成品页的语义项

T2～T4 和 L5 报出的只是候选，下面的标准同时也是裁定这些建议的依据。

1. **加点（•）只给长的、并列的语义句**（SD-78，用户：「加点只限于长的、并列的语义的句子」「要结合语义去判断是否有多个并列的语义」）。
   - 一格里有两个以上各自独立的判断、条件或动作，才分条加「•」。
   - 短状态（如「ALTN 电门亮」）、标签格、带因果或转折的连续叙述（但 / 因此 / 即 / 其中 / 否则 / 而……）不加点。
   - 「引语：子项；子项」写成引语一行，下面列「–」子项。
   - 真正的时序步骤用 ①②③，不与「•」混用。
2. **居中看信息职责，不只看字数**（SD-75）。单一紧凑短句的列（原理 / 状态 / 现象 / 结果……）整列居中。段落、列举、例外、因果展开左对齐。「条件」列要看内容，不能机械地左对齐或居中。
3. **颜色只由显式标记决定**（SD-75）：`<em>` 红色表示边界、警戒、硬性动作；`<b>` 亮蓝表示记忆值；`<strong>` 表示一般黑粗。不因为是数字就标蓝，不整句标红。
4. **黄色底**：需要特别注意的只标那一两格（`<td class="hl">`），不整行铺黄；整行黄底只留给 `class="warn"` 警示通栏行（SD-99）。颜色同义同色、速查与正文同值同色见 SD-98。
5. **层级符号**「▪ 主题 / – 子项」只用于「短主题：」后接两条以上平行条件（SD-75）。
6. **表后的注、解释、出处紧跟表格同页**。同一条目的两张表跨页、表后说明段跨页属正常，不算 B 类错误。
7. **一页放得下的表整表移到下一页，上一页因此留白**，这是 SD-71 的既定代价，不算问题。
8. **源文件**：行首不写项目符号（符号只由渲染器加），`<br>` 主动分行不要滥用，机型标签用全角【737-NG】【737-8】（SD-11）。
9. **内容规则**不在本清单，见 `AI校对指令_通用.md`：数值原样照录、两型不默认相同、只以本地手册库为据。

## 三、每轮收工前

- **速查区改了，后续章节一并改**（SD-92）：速查区做任何更改或优化，都必须检索第 1～5 章里对应的内容，包括「详见」指向的条目和出现同一数值、同一术语的其他位置，一并修改；改排版标注的，正文同表也要标（S5）。sync 前会自动运行 `quickref_sync_hint.py` 列出要核对的位置。

- 检查器错误 = 0；建议逐条有结论（改了，或写明不改的理由）。
- 在 `00_先读我_AI交接.md`「每轮工作记录」顶部写本轮记录，记下报告里的错误数和建议数。
- 用户新提出的排版要求，先加进本清单和 `check_layout.py`，再改成品。只改成品不加规则，同样的问题还会再出现。
